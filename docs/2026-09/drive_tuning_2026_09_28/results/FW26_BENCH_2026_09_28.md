## T3.4 / B8 hall velocity filter (param 136 period, 137 depth)
- The factory value of 136 is raw 0x3EA00000 = 0.3125. **The controller rejects writing 0.3125 (`res=4 invalid`)**; the valid range is 0.008–0.064 s. It behaves exactly like the documented 0.03125 s default (same 72 ms lag at depth 2), so it is a legacy factory value, not a real 0.3125 s window.
- At depth 2: period 0.03125 → **72 ms** lag (reported-speed σ 6–7 RPM); period 0.016 → **32 ms** (σ 11 RPM). Both 136 and 137 are honoured on FW 26.

## Native kS at zero: follow-up and correction (2026-09-28)
Research: `research/evidence/firmware_can_review_2026_09_27/KS_AT_ZERO_2026_09_28.md`. **Verdict: the controller works as REV designed. No firmware bug, and our CAN frames were correct.**
- REVLib 2026.0.5, which REV says is "translated directly from the Spark firmware": `sgain = copysignf(kS, state.velocity)`, where velocity is the setpoint in velocity mode. So +0.0 gets +kS; there is no deadband and no gate (param 97 does not disable it).
- REV docs: kS is applied "in the direction of desired velocity", tuned "so that it doesn't move on its own". WPILib's `kS·signum(v)` (0 at 0) is a different convention, and assuming it was our error.
- Controlled bench variants (STATUS_8 confirmed the SPARK received exactly 0.0):
  - fresh, after +100, after −100: always +kS at 0;
  - ±0.001, ±0.01, ±0.5 RPM: ±kS, confirming no deadband;
  - native kS = 0: perfectly still.
- **Sized correctly, native kS does not move the tracks at 0:**

| native kS at a 0 command | kS only | kS + final gains |
|---|---|---|
| 0.12 V | 0 / 0 RPM | 0 / 0 |
| 0.18 V | 0 / 0 | R creeps 8 |
| 0.24 V | R creeps 23 | R creeps 13 |
| (0.30 V, B3) | creeps 42–70 | — |

**Design choice (not a safety rule):**
- A kS fitted from data equals the breakaway voltage, and that is what low-speed tracking needs (0.18 V fixed sticking, T2.6). With native kS, the same value sits right at breakaway whenever a track's target is exactly 0 (turn-in-place crossings, the inner track of tight arcs), giving marginal creep.
- The Teensy arbFF kS is exactly 0 at a 0 target, so it can use the full fitted value.
- Native kS remains valid if kept a little below breakaway, stopping with duty 0/Brake (as `S` and the watchdog already do), and **never together with the arbFF kS** (they add; test B5).
