## 3. BURN persists across a power cycle
1. Marker `kDFilter = 0.2` (no effect while kD = 0) was written and BURNed: `OK BURN result L=0 R=0`.
2. The robot was power-cycled (Jetson journal ends abruptly at 12:45:57). Both controllers then reported the sticky warning **HAS_RESET**, which proves they lost power.
3. The marker **still read 0.2** on both.
4. Restored to 0 and BURNed again (`result 0/0`).

**BURN works, and the saved values survive power loss.**

## 4. Stopping: root cause of the "back-and-forth" and the DRV faults
Bench, from 2000 RPM:

| Stop method | Overshoot past 0 | Reversals | Settles in | Peak current | Min bus V | DRV fault |
|---|---|---|---|---|---|---|
| `S` = velocity 0, instant (v1/v2 behaviour) | −480 RPM | 7–9 | > 2 s | 46–57 A | 7.9 V | **yes** |
| velocity target ramped to 0 (Teensy slew) | −110 | 0–1 | 1.2 s | 33 A | 10.4 V | no |
| `S` + hall depth 1 (old gains) | −2240 | 28 | unstable | 93 A | 7.1 V | yes |
| ramp + hall depth 1 (old gains) | −1943 | 28 | unstable | 93 A | 6.2 V | yes |
| `S` + closedLoopRamp 2 | −630 | 5–7 | > 2 s | 15 A | 11.1 V | no |
| **duty 0 + Brake idle** | **0** | **0** | **0.25–0.30 s** | 7–12 A | 11.2 V | no |
| duty 0 + Coast idle | −11 | 0 | 0.4 s | 8–10 A | 11.4 V | no |

**Root cause:** a velocity-0 step drives the speed PID to full reverse. With about 140 ms of measurement lag and P = 0.0007 it overshoots and rings. The braking current sags the motor bus to about 7–8 V, which trips the DRV (gate driver) faults.

The DRV hunt (8 isolated cases) confirmed it: every stop through the velocity PID (S from speed, reversal) set a DRV sticky fault; stops through idle (coast or brake) never did.

## 5. The reference-standard setup
Standard per the research:
- feedforward first, P below the oscillation point, no I (C1 practice 18);
- Brake idle (C3-S48);
- REV current limit 40–60 A (C1 practice 13);
- stop = controlled decel, then idle/brake at standstill (IEC 61800-5-2 SS1 pattern; Nav2 smoother and diff_drive ramp to zero; C3 §7).

### 5a. P sweep (I = 0, Brake, 50 A), off the ground
| Setup | Steady error at 1000 / 2000 RPM | Step overshoot | Speed ripple | `S` stop | Ramp-then-brake stop | DRV |
|---|---|---|---|---|---|---|
| **Current** P 0.0007, I 2.5e-7, coast, 80 A | +0.2 % / +0.1 % | 18–25 % | **±100–214 RPM** | 8–10 reversals, > 2 s | −177 RPM, 0.9 s | yes |
| P 0.0001 | +1.0–1.7 % / +3–4 % | 9–11 % | ±6–11 | 1 reversal, 0.55 s | −65, 0 reversals, 0.68 s | no |
| P 0.0002 | +0.6–1.4 % / +2.5–2.9 % | 11–16 % | ±6–14 | 1–2 reversals | −78, 0 reversals | no |
| P 0.0004 | +0.6–0.9 % / +1.7–2.1 % | 13–21 % | ±11–17 | 3–4 reversals | −77, 0 reversals | no |
| P 0.0007, I 0 | ±0.3 % | 16–23 % | ±94–180 (oscillates) | 5–10 reversals | −134 | yes |

**The oscillation comes from P = 0.0007, not only from I.** The oscillation onset is between P 0.0004 and 0.0007, so the standard choice (back off from onset) is about **0.0003**. The step overshoot here comes from the Teensy slew (5000 RPM/s); actuator_node's ramps are gentler.

### 5b. Firmware v2b: `S` and watchdog stop to idle
v2b is v2 with `STOP_TO_IDLE = true`. `S` and the 300 ms host watchdog set duty 0, so the SPARK's idle mode stops the motor. The next L/R command resumes velocity mode from 0. It compiles with 0 warnings. It is flashed on the Teensy now; the v2 image is kept for rollback (`~/fw_v2`).

### 5c. Stops through the real pipeline (`/cmd_vel` → actuator_node → Teensy → SPARK)
| Case | **A: current** (v2, P 0.0007, I on, coast, 80 A) | **B: standard** (v2b, P 0.0003, I 0, IZone 0, brake, 50 A) |
|---|---|---|
| 0.6 m/s, then cmd_vel stops (timeout) | −370 RPM past 0, standstill after **2.6 s** | −190 RPM, **1.0 s** |
| 0.6 m/s, then cmd_vel = 0 | −750 RPM, **3 reversals**, 2.1–2.4 s | −240 RPM, **0 reversals**, **0.9 s** |
| turn 0.8 rad/s, then 0 | −89 RPM, 0.8–1.1 s | −72 RPM, 0.74 s |
| 1.0 m/s, then cmd_vel = 0 | −440 RPM, 2 reversals, 2.5 s | −180 RPM, 1 reversal, 1.1–1.2 s |

The standard setup stops **2–3× faster with little or no back-and-forth**. A small backward dip remains at the end of the slow-down (about 200 RPM ≈ 7 cm/s briefly). It comes from P plus the 140 ms speed-reading lag.
